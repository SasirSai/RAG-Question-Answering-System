# Consistent Hashing: Design, Virtual Nodes, and Ring Topology

## 1. The Scaling Problem with Modulo Hashing
In distributed storage and caching clusters, mapping keys to N physical nodes using conventional modulo arithmetic (node = hash(key) % N) creates catastrophic rehashing cascades when nodes are added or removed: almost every single key maps to a new node index, causing complete cache invalidation and severe database stampedes.

## 2. Consistent Hashing Ring Concept
Consistent Hashing, introduced by Karger et al. in 1997, decouples cluster size from key placement:
- The hash function maps both physical servers and data keys onto a continuous circular numeric identifier space called the hash ring (typically a 32-bit or 128-bit integer space from 0 to 2^128 - 1).
- A key's location on the ring is determined by hash(key).
- To locate the server responsible for a key, the system walks clockwise along the ring from the key's position until encountering the first server node.
- **Node Addition / Removal Property:** When a node is added or removed, only K / N keys need to be remapped on average (where K is total keys and N is total servers), preserving 100% of unaffected mappings.

## 3. Virtual Nodes (Vnodes)
A primary challenge with basic consistent hashing is non-uniform data distribution and hotspotting caused by unevenly spaced node positions along the ring.
- **Virtual Nodes Solution:** Instead of assigning each physical server a single ring location, each physical machine is assigned multiple virtual positions (e.g., 100 to 256 virtual nodes) generated by hashing tokens like node_ip#vnode_1, node_ip#vnode_2.
- Virtual nodes distribute partitions evenly across the entire key space, balancing storage load and allowing heterogenous servers with higher hardware specs to hold proportionally more virtual nodes.
